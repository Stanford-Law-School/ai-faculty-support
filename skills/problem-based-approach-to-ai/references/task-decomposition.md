# Task decomposition

A workflow is not one thing. Break it into tasks so that each can be matched to the right approach — and so AI is considered only for the tasks it actually fits.

## Task types

Intake, search, retrieval, sorting, classification, extraction, summarization, comparison, drafting, reformatting, calculation, judgment, decision, approval, communication, publication, recordkeeping, monitoring, escalation.

## Decomposition table

| Task | Frequency | Judgment | Stakes | Data sensitivity | Verifiability | Candidate approach |
|---|---:|---|---|---|---|---|

- **Judgment:** none / some / high — how much human legal or pedagogical judgment the task requires.
- **Stakes:** low / medium / high — consequence of an error.
- **Data sensitivity:** public / internal / confidential / restricted.
- **Verifiability:** easy / moderate / hard — how easily a human can check the output.

## Candidate approaches

Human judgment; process improvement; search; template; database; rules-based automation; retrieval; generative AI assistance; predictive model; constrained agent; external specialist; stop performing the task.

## Rules

- Do not recommend AI merely because a task involves text.
- Tasks that are high-judgment, high-stakes, and hard to verify usually stay human.
- Repetitive, low-stakes, easily verified, public-data tasks are the strongest AI candidates.
- Separate a task the AI drafts from the decision a human must still own.
- A single workflow may end with several different approaches across its tasks — that is a good outcome, not a failure to pick one tool.

Carry the candidate approaches into capability matching and suitability assessment.
