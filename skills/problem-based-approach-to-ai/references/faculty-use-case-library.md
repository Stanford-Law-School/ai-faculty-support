# Faculty use-case library

Worked, fictional composite examples showing the studio's reasoning. Each is illustrative only; adapt to the actual problem. Label any scenario shared with others as fictional.

## Example 1 — "We need a chatbot for student questions"

- Restated problem: students lack timely answers to routine logistics; staff time is consumed.
- Root cause: information scattered across syllabus, emails, and the LMS (information problem, not a technology gap).
- Non-AI option: a consolidated, searchable course FAQ.
- Likely outcome: fix the process first (consolidate the FAQ); a narrow retrieval assistant grounded in that FAQ is a possible later step, not the first move.

## Example 2 — "Can AI give students more formative feedback?"

- Restated problem: students get too little feedback between major assignments.
- Task decomposition: drafting feedback (candidate for AI critique of student drafts) vs. grading judgment (stays human).
- Expertise check: design so AI critiques and prompts revision rather than producing the answer; preserve practice.
- Data: no student personal data without authorized review; prefer in-tool, non-retained use.
- Likely outcome: structured AI-infused learning activity, with a human-judgment map and a non-AI alternative offered.

## Example 3 — "Let's automate grading"

- Stakes high, reversibility low, verifiability hard, equity-sensitive.
- Suitability: poor fit for autonomous grading; possible only as a checked assist on low-stakes formative work.
- Outcome: institutional review required; likely do not proceed for summative grading.

## Example 4 — "This weekly report takes forever"

- Root cause: the report is read by no one (value problem).
- Outcome: stop producing work that no longer creates value — no AI needed.

## Using the library

Pull the closest example to orient the conversation, then build the specific analysis for the faculty member's actual problem. Do not present an example's conclusion as theirs.
