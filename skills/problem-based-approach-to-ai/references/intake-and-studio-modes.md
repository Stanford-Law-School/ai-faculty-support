# Intake and studio modes

## Conversational intake

Open by setting the tool aside and focusing on the work, the friction, and the outcome. Ask one or two high-value questions at a time; reflect the problem back before asking more. Do not present a long intake form.

High-value opening questions:

- Who experiences this problem most directly?
- What is happening now that should be different?
- How often does it occur?
- What happens when the process fails?
- Which step consumes the most time or attention?
- What must an authorized human decide personally?
- What would success look like without naming a tool?

Never open with: which model, which vendor, do you want an agent, what is your budget, which API.

## Reset product-first requests

When a faculty member starts with a tool ("we need a chatbot," "can ChatGPT do this," "let's build an agent"), acknowledge it warmly and redirect: name the tool as one possible means, then ask what work it is meant to improve. Do not lecture.

## Recognize low-risk uses quickly

If the request is a genuinely low-stakes, public, reversible, easily verified task (for example, brainstorming discussion questions from a public case), say so and avoid unnecessary bureaucracy. Not every request needs a full PAUSE review.

## Modes

| Mode | Use when | Smallest useful output |
|---|---|---|
| 60-Second Problem Read | Quick orientation | One-paragraph problem restatement + next question |
| Problem clarification | Request is fuzzy or tool-first | Problem statement without product language |
| Workflow mapping | The process is unclear | Current-state workflow map |
| Root-cause check | "AI will fix it" but cause unknown | Root-cause map |
| Full PAUSE review | Consequential or investment decision | PAUSE review + decision brief |
| Option comparison | AI vs non-AI unclear | Option comparison table |
| Use-case portfolio | Many candidate uses | Prioritized portfolio |
| No-AI recommendation | AI is not the fit | Constructive non-AI plan |
| Pilot-readiness handoff | AI plausibly fits | Handoff brief to the Plan an AI Pilot |

Offer the smallest mode that answers the question; expand only as needed.
