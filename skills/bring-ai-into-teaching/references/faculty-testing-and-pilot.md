# Faculty testing before use

Faculty should run the activity themselves before assigning it. AI behavior, access, and timing vary, and an untested activity can fail in class or disadvantage students.

## Test before assigning

- Current product behavior
- Access requirements
- Account-tier differences
- Output variability
- Likely failure cases
- Source verification
- Time requirements
- The no-tool alternative
- Accessibility
- Student instructions (clarity)
- Debrief timing
- Data boundaries
- Likely misconceptions

## Rules

- Test from a student's perspective and access level, not the instructor's.
- Confirm the no-tool alternative actually works and is equivalent.
- If the activity depends on a current product, re-test after known product changes.

## Handoff

For substantial, multi-case representative testing (many inputs, thresholds, reviewers), route to the Plan an AI Pilot; this reference covers the faculty member's own pre-use check.
