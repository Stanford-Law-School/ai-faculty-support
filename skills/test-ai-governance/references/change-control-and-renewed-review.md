# Change control and renewed review

Governance is tied to a specific configuration and context. A material change can invalidate prior assumptions, so define what triggers renewed review.

## Material-change triggers

Purpose; users; affected people; data; product; model; account tier; retrieval collection; system instructions; permissions; connected services; external actions; human-review process; vendor terms; retention; logging; accessibility; failure rate; applicable law; Stanford guidance.

## Principles

- A vendor update is not automatically immaterial; assess it.
- After a material change, determine which earlier tests and permission grants must be re-examined.
- Decide explicitly whether use may continue during review, and record it.
- Keep a small set of high-stakes checks to rerun after any trigger.

## Boundary

This reference governs when to re-review, not who authorizes continued use; name the authorized role or mark it "institutional confirmation required."
